## 3. 驱动侧修掉的两处（都会让判据失真，不是放宽）

1. **`jdbcJar()` 挑到了不存在的 jar**：按字符串排序取最后一个版本 → 选中 `9.7.0`，而 `~/.m2` 里
   9.7.0 **只有 `-sources.jar`**（8.3.0 才有二进制），java 起来就失败。改为只认**真的有二进制 jar** 的版本。
2. **`PHONE_RAW` 与 `PHONE_FLAT` 不是同一个号码**（L17 的根因）：布景写的是
   `'+86 138-0000-0907'` → 归一后 **13 位 `8613800000907`**，而客户 C 的 `PHONE_FLAT` 是
   **12 位 `861380000907`**，两者永远比不中 ⇒ L17 恒为 0 行。
   这条最危险的地方是**会被误读成"8b ⑧ 的 `normalizePhone` 没落地"**——可库里存的分明是归一值
   （`phone="861380000907"`，没有 `+` 与分隔符），归一本身是好的。
   改 `PHONE_RAW = '+86 138-0000-907'` 后 **L17 转绿**。
   顺带修了诊断读数：`GET /group/members` 返回的是 `MemberPageVO{members,coverage,reason}`，
   列表在 `data.members.records`；按 `rec()`（`data.records`）取会拿到 `[]`，看着像"这一行不存在"。
